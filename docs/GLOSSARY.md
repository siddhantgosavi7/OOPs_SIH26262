# Glossary

| Term | Meaning |
|---|---|
| **AICTE** | All India Council for Technical Education |
| **APH** | Approval Process Handbook (2024-25 to 2026-27) governing approvals |
| **NSWS** | National Single Window System (route for new institutions) |
| **EoA** | Extension of Approval |
| **EVC** | Expert Visit Committee — inspects institutions for certain approval categories |
| **LoA / LoD / LoR** | Letter of Approval / Deficiency / Rejection |
| **Scrutiny / Re-scrutiny** | Officer review of an application, and its repeat after a deficiency response |
| **Deficiency** | A shortcoming an institution must fix before approval |
| **Undertaking** | A commitment by an institution, with a deadline |
| **Affidavit 2** | A required affidavit mentioned in the approval process |
| **DSC** | Digital Signature Certificate |
| **APAAR / DigiLocker** | Government ID / document systems (not integrated; mocked) |
| **SIH** | Smart India Hackathon |
| **SLA** | Service-level agreement — time allowed for a stage |
| **Pendency / ageing** | How long a case has been pending in a stage / overall |
| **COI** | Conflict of interest (e.g. expert tied to the applicant) |
| **Finding** | A rule result shown to an officer; never changes a case by itself |
| **Rule version** | Immutable snapshot of a rule; edits create a new version |
| **ASSUMED / VERIFIED** | Rule status: not yet tied to a verified APH clause / tied to one |
| **Clause map** | File linking each rule to its APH clause and page |
| **Dedupe key** | Unique key making alert creation idempotent |
| **Idempotent** | Running an operation again has no additional effect |
| **Hash chain** | Each record includes the previous record's hash, making edits detectable |
| **Process mining** | Analysing event logs to find real process paths and delays |
| **Conformance checking** | Comparing actual traces with the prescribed process |
| **Token replay / alignments** | Two conformance-checking techniques (fast vs precise) |
| **CP-SAT** | OR-Tools constraint-programming solver |
| **SimPy** | Python discrete-event simulation library |
| **RBAC** | Role-based access control |
| **Scoping** | Restricting data to a user's region/institution |
| **Ed25519** | Modern digital signature algorithm |
| **Mock adapter** | Stand-in implementation of an external system |
| **Synthetic data** | Artificially generated data with no real persons/institutions |
| **Gold set** | Dataset with known, seeded defects used to measure detection |
| **D1–D5 / C1–C9** | Differentiator / core feature IDs used throughout the docs |
